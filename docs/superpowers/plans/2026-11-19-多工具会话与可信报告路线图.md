# WorkWeave 多工具会话与可信报告开发路线图

> 本方案按阶段交付。第一期先建立多来源会话数据底座和可查询 MCP 工具；第二期完善证据包、宿主结果校验与事实降级闭环；第三期再评估 Git 交叉引用和用量成本分析。

## 项目目标

把多个 AI 编程工具散落在本机的会话统一采集、保存、检索和按项目归类，再逐步形成可追溯、可校验、模型不可用时仍可使用的工作总结。

WorkWeave 的核心价值是“总结可信”。采集广度是能用的前提，证据包和宿主校验是差异化壁垒；成本、Token 和 Git 指标用于增加信息密度，不能抢占核心路径。

## 分期原则

| 阶段 | 交付目标 | 必须包含 | 暂缓内容 |
|---|---|---|---|
| 第一期：多工具会话底座 | 能采、能存、能查、能跨工具精确去重 | 可由 CLI/MCP 触发并支持续采的采集入口；Windback 式统一会话存储及列表/读取/搜索 MCP 工具；ChatWizard 式多来源适配；Aiscribe 的原生连接器覆盖广度 | 语义去重、宿主叙述校验闭环、成本估算、Git 交叉引用 |
| 第二期：可信总结闭环 | 总结每一项有证据，失败时安全降级 | 结构化证据包、宿主生成结果校验、失败重试/拒绝落盘、未经语义总结的事实模式 | 成本/Token 分析、模型排名 |
| 第三期：可选信息增强 | 在核心报告稳定后提高报告信息密度 | devday 式 Git 变更交叉引用；AgentRecap 式 Token、模型和 API 等价成本分析 | 将成本或提交量用于绩效结论 |

各期独立验收。第二期依赖第一期统一的会话、来源和消息 ID；第三期依赖稳定的会话元数据与报告结构。第二、三期不阻塞第一期发布。语义去重列为第三期可选增强，与可配置的本地 embedding backend 同步交付；第一期不引入 embedding 依赖。

## 第一期：多工具会话数据底座

### 1. 统一存储与 MCP 查询

- 将所有适配器输出归一为会话、消息、来源、项目路径、模型/工具元数据；同一来源的会话使用 `(sourceTool, sessionId)` 作为稳定身份，不同来源即使 session ID 相同也不能误合并。
- 使用本地 SQLite 持久保存会话索引和消息。写入采用事务与增量 upsert；重采集不重复产生同一条记录。原始来源文件保持只读。
- 增加三个 WorkWeave 命名空间 MCP 工具：`ww_sessions_list`、`ww_session_read`、`ww_sessions_search`，分别对应 Windback 的 `list_sessions`、`read_session`、`search_sessions` 使用模式。
- 列表支持日期、来源、项目和分页过滤；读取支持会话 ID、分页和消息数上限；搜索支持关键词/全文检索、来源/日期/项目过滤及结果数量上限。
- MCP 返回内容按调用目的最小化：列表只返回元数据；搜索只返回命中片段和引用；读取才返回请求范围内的消息，并设置最大消息数/字数。读取和搜索使用现有 egress 权限、脱敏与审计边界。
- 为历史数据设置本地保留和清理接口；删除只作用于 WorkWeave 自己的 SQLite，不修改来源日志。

### 2. 最小可用采集入口

- 提供两个可触发入口：CLI `workweave ingest --day=YYYY-MM-DD [--source=<source>]` 和 MCP `ww_source_ingest`。两者进入同一 runtime/service，使用相同适配器、幂等键、进度状态和错误分类；报告导出可以调用该入口，但不能另建一套采集逻辑。
- 采集按“来源 × 文件/会话”划分事务单元。单元完成并写入 SQLite 后立即提交 checkpoint；进程中断后从最后已提交单元继续。源文件以路径、大小、修改时间和内容指纹组合识别变化，文件变化时重新解析并幂等 upsert。
- 每次运行记录 `runId`、日期范围、来源、状态、已扫描/成功/失败单元数、checkpoint、尝试次数和脱敏错误码。运行记录不保存会话正文。
- 瞬时 I/O 错误和数据库忙锁按有限次数指数退避重试；格式错误、版本不支持、权限拒绝作为单元失败记录并继续其他单元，不无限重试、不静默吞错。支持 `--resume`/`resume=true` 续跑未完成运行。
- 即使同一文件在崩溃前已写入但 checkpoint 尚未推进，重试也不得重复会话或消息；必须先完成幂等 upsert，再推进 checkpoint。

### 3. 多来源原生连接器

以 Aiscribe 的本地连接器覆盖和 ChatWizard 的适配器注册/统一索引模式作为覆盖目标。第一期目标清单如下；复用既有解析器的 schema 测试和取证要求，不凭名称宣称支持。

| 来源 | 首期目标连接器 |
|---|---|
| Aiscribe 连接器 | CodeBuddy CN、TRAE、Codex、dsh、Claude Code、Gemini CLI、Qwen Code、iFlow、Copilot Chat、Cline、Roo Code、Kilo Code、Cursor、Doubao、WorkBuddy、Kimi |
| ChatWizard 补充连接器 | Windsurf、Continue.dev、Amazon Q Developer、Gemini Code Assist、Aider、Google Antigravity |
| 非会话活动证据 | Aiscribe 的 Windows Recent Files（作为独立活动来源，默认只采集路径元数据；不读取文档正文） |

连接器覆盖目标是上述 22 个会话来源，加一个可选的 Windows 文件活动来源。现有 `codex`、`dsh`、`workbuddy` 适配器优先复用；Claude Code 继续执行取证门禁；其余连接器按本地数据格式分批接入。每个来源输出 `discovered / unsupported / unavailable / possibly-incomplete` 能力状态，不能将未实现或未验证的来源显示为零会话。

每个连接器必须有最小真实格式 fixture，覆盖探测、解析、日期、session ID、消息角色、时间戳、项目路径和异常/版本降级。来源日志可能含敏感文本，fixture 必须脱敏，测试不能提交真实个人会话。

### 4. 第一期精确去重

- 用来源事件 ID、message ID 和规范化正文哈希识别同源重放；对跨工具完全相同的用户提示生成精确重复组。跨工具提示只有在规范化文本完全相同、同一已识别项目（项目未知时不跨项目合并）、时间相差不超过 10 分钟时才折叠展示。规范化只统一换行、首尾空白和 Unicode NFC，不删除有语义的标点、代码或参数。
- 精确去重只影响合并视图和搜索结果的折叠展示，不物理删除或覆盖会话/消息；每个原始消息仍可独立读取，且保留全部来源引用。
- 不做近似词项或 embedding 相似度判断。第一期搜索不能把相似但不同的请求标成重复。

### 5. 跨来源合并视图展示规则

- 原始会话和消息是不可变来源记录。合并视图是由精确重复键生成的展示层分组，不创建一个取代原记录的“合并消息”。
- 列表中的合并项显示统一摘要、时间范围和来源标签；每个来源标签都能展开到 `sourceTool`、`sessionId`、`messageId`。MCP 搜索返回命中条目时也带完整来源引用数组，不能只返回被选为主记录的一条引用。
- 精确重复的用户提示可以折叠显示一次正文，旁边列出全部来源与命中时间；不同来源的助手回复、工具调用和结果仍分开展示，并分别关联所属来源会话。
- `ww_session_read` 读取单一来源会话，不返回跨工具拼接的对话流；跨来源聚合读取由搜索/合并视图提供分组及引用列表，用户可逐条读取原会话。
- 日报按项目聚合时，每个事实条目显示来源数/来源标签；点击或展开后列出原始引用。排序和折叠不能改变原生消息数、事实数或证据引用。

### 6. 第一期验收标准

- 至少两个不同 AI 来源可以采集并进入同一个本地 SQLite 会话索引；已支持来源按配置统一生成日报数据。
- CLI 和 MCP 均可触发同一个采集入口；成功重跑幂等；在解析、写入或 checkpoint 推进处注入中断后可续采；瞬时错误按有限策略重试，永久格式错误隔离并报告。以上均有自动化测试。
- `ww_sessions_list`、`ww_session_read`、`ww_sessions_search` 可由 MCP `tools/list` 发现并成功调用；过滤、分页、上限和 egress 权限均生效。
- 重复扫描幂等；跨来源相同 session ID 不冲突；完全相同的跨工具用户提示可折叠展示，但打开后仍可读取每个来源的原始消息和引用。
- 连接器支持矩阵准确显示覆盖状态；未适配来源不会伪装为“无记录”。
- 第一期不下载、不加载 embedding 模型；搜索与精确去重不依赖 embedding。
- 原始来源文件不被改写；SQLite/搜索响应遵守内容上限和脱敏策略；测试 fixture 不含真实私人文本。
- Windows、macOS、Linux 上执行构建、Lint、完整测试和 no-model/本地数据边界检查。

## 第二期：证据与可信总结闭环

### 交付范围

- 生成结构化证据包：最小必要片段、证据 ID、来源/消息/时间引用、置信度、脱敏状态、完整性声明。每条证据明确带 `sources: [{ sourceTool, sessionId, messageId }]`；聚合证据可以有多个来源引用。
- 宿主只能基于证据包生成叙述；新增中文输出模板，按“结论先行、三类支撑、重要性/因果顺序”组织内容。
- 校验章节完整性、证据引用存在性和语义关联、数字一致性、日期/状态合法性、隐私/禁用表述；校验失败不落盘，给出可重试的具体错误。
- 连续重试失败、宿主不可用或未返回时输出事实降级报告，明确标记“未经语义总结”，保留空类别原因和证据引用，不伪造产出。
- 让降级模板与宿主总结共享同一份结构化报告模型，保证两种路径都可核验。

### 参考与边界

- 参考 Halowake 的零 token 本地解析、Aiscribe 的“本地模板/AI 叙述”分层和 WorkWeave 已有证据包/validator。
- 第二期不是重写已有 evidence/validation 代码；先审计现有实现与场景测试，补齐缺口并形成真正的失败重试和降级闭环。
- 校验闭环自行实现，不复制参考项目代码；宿主生成文本不因产品需要而放宽引用或敏感信息约束。

### 第二期验收

- 报告中的每项结论均能由一个或多个证据 ID 回查；失效引用、冲突数字或无证据陈述拒绝落盘。
- 校验失败时可重试；超过配置上限后确定性降级，仍生成完整结构并标注未经语义总结。
- 宿主不可用、输出为空、连续格式错误、恶意会话文本提示注入等场景都有自动化测试。
- 工作流在无模型依赖/无 API Key 情况下仍可产出事实报告。
- 每条证据包条目都保留 `sources` 原始引用数组；宿主叙述引用聚合证据时，回查能定位到数组中的每个原始来源记录。
- 跨来源相同提示在证据包中可聚合展示，但不能重写来源 `sessionId` / `messageId`，不能把多条来源压成一个伪造的来源 ID。

证据包字段形式：

```json
{
  "id": "ev-123",
  "text": "脱敏后的最小必要事实片段",
  "sources": [
    { "sourceTool": "codex", "sessionId": "session-a", "messageId": "message-a" },
    { "sourceTool": "workbuddy", "sessionId": "session-b", "messageId": "message-b" }
  ]
}
```

`sources` 中的每个三元组必须能独立回查。聚合条目可以有多个来源，但不得更改原始 ID；单来源证据也使用数组形式，避免两套 schema。该字段作为第二期证据包固定契约，并按用户指出的 `spec.md` 6.14 结构保持一致。当前仓库未找到 `spec.md` 文件，因此实施前需将证据条目的其他字段与该规范逐项核对；`sources` 字段按本方案示例固定。

## 第三期：可选增强

### Git 交叉引用

参考 devday，将会话内的仓库路径、文件变更、提交 ID 与本地 Git 提交关联，作为事实补充。只读 Git 元数据；无法关联时显式标未知；不得把提交数量当作工作质量。

### 用量与成本分析

参考 AgentRecap 增加 Token 输入/输出、来源和模型对比、缓存/推理 Token（仅日志原生记录时）、工具调用图表及 API 等价成本估算。原生 Token 和文本长度估值分开标注。缺少原生 Token 时，CJK 字符逐字估算、ASCII/Latin 每四个字符约估算为一个 Token，system/developer 消息和脱敏块不计；隐藏提示、上下文重放、缓存和隐式工具上下文不在估算内。模型 ID 或价格缺失时显示未计价，不套用默认模型价格。价格采用注明来源和日期的本地快照，不在运行时查询网络。费用使用 USD，表示 API 参考成本，不代表订阅账单。

第三期需基于第一期统一事件模型实现，不得侵入第二期证据和宿主 validator；费用只用于用量参考，不用于绩效判断。

### 可选语义去重与本地 embedding

- 仅在第三期资源允许时实现；依赖第一期稳定的精确重复分组和跨来源引用结构。
- embedding backend 使用接口注入，可选加载用户本地配置的模型；未配置时明确返回“语义覆盖不可用”，精确去重和全文搜索继续工作。
- 禁止运行时下载模型或调用远程 embedding 服务。模型/算法版本变化后重建独立索引，不混用向量。
- 语义相似只产生可解释的候选簇，不能自动合并原始会话、消息、证据、Token 或成本数据。
- 验收覆盖：无 backend 的精确去重 fallback、有 backend 的相似候选、模型维度/版本隔离、隐私边界和候选簇可回查。

## 参考项目

- [Windback](https://github.com/kesh-007/windback)：本地统一会话存储及 `list_sessions` / `read_session` / `search_sessions` MCP 模式。
- [ChatWizard](https://github.com/Veverke/ChatWizard)：多来源适配器注册、统一索引、embedding 候选聚类和本地搜索。只参考架构与行为；检查其许可证，不复制代码。
- [Aiscribe](https://github.com/5yeah/Aiscribe)：16 个 AI 工具连接器和 Windows Recent Files 活动来源；Aiscribe 使用 MIT 许可证，接入仍以格式验证和独立实现为准。
- [Halowake](https://github.com/zhkai-ybwn/Halowake)：零 token 本地会话解析与可编辑事实。
- [AgentRecap](https://github.com/bansalarnav/agentrecap)：metadata-only 的成本、Token、模型和工具调用报告。
- [devday](https://github.com/ujjwaljainnn/devday)：会话与 Git 变更交叉引用。

## 方案约束

- 多来源数据必须保留来源身份；合并视图不能抹去原始来源、模型和证据引用。
- 参考实现只用于产品行为和架构调研；实施前逐项核对许可证，优先独立实现接口与数据格式。
- 第一、二期不接入 embedding 模型、云端 LLM API 或运行时价格查询；第三期语义去重也只允许可选的本地 embedding backend。任何需要把会话发到外部服务的方案必须另行评审。
- 数据库持久化、MCP 读取和搜索都必须遵循最小权限、分页、输出上限、路径防护和隐私脱敏。
- 新增来源必须以 fixture、格式版本和覆盖状态为依据；不以 README 中列出的来源数量代替实际可用性。
